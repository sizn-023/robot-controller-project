# 机器人软件测试设计

## 1. 项目概述

本项目用于模拟机器人软件测试岗位中的测试工作。

测试对象主要包括：

- 机器人控制器
- 工业控制器
- Teach Pendant 示教器

项目重点模拟机器人软件基础功能测试、异常测试以及自动化测试。

---

## 2. 测试目标

本项目的测试目标包括：

1. 验证机器人控制器基础功能是否符合预期。
2. 验证工业控制器相关功能是否正常。
3. 验证 Teach Pendant 工作模式切换是否正确。
4. 通过正常、边界和异常场景发现软件缺陷。
5. 使用 pytest 编写自动化测试用例。
6. 使用 Git 管理测试项目代码和测试文档。

---

## 3. 测试范围

### 3.1 机器人控制器

测试以下功能：

- 初始状态
- 启动机器人
- 停止机器人
- 机器人运动
- 运动前置条件
- 电池状态检查
- 电量不足处理

### 3.2 工业控制器

测试以下功能：

- 初始状态
- 启动
- 停止
- 机器人运动
- 运动距离校验
- 电池消耗
- 边界电量测试
- 异常输入处理

### 3.3 Teach Pendant

测试以下功能：

- 初始模式
- AUTO 模式
- MANUAL 模式
- 模式切换
- 非法模式输入
- 重复切换
- 无效输入后的状态保持

---

## 4. 测试类型

### 4.1 正常测试

验证正常输入和正常操作下，系统是否能够按照设计要求工作。

例如：

- 正常启动机器人
- 正常停止机器人
- 输入有效运动距离
- 正常切换工作模式

### 4.2 边界测试

验证系统在临界条件下的行为。

例如：

- 运动距离为 0
- 电池电量处于临界值
- 电池电量为 1%
- 电池电量为 99%

### 4.3 异常测试

验证系统面对非法输入或异常状态时是否能够正确处理。

例如：

- 负数运动距离
- 非法工作模式
- 电量不足时运动
- 未启动时执行运动

---

## 5. 测试重点

本项目重点关注以下方面：

1. 功能正确性
2. 边界条件处理
3. 异常输入处理
4. 状态切换正确性
5. 前置条件校验
6. 电池消耗逻辑
7. 自动化测试覆盖率

---

## 6. 测试策略

采用黑盒测试与自动化测试相结合的方式。

测试设计阶段首先根据功能需求设计测试点和测试用例。

随后使用 pytest 编写自动化测试。

测试执行后记录测试结果，并通过测试报告和代码覆盖率评估测试效果。

---

## 7. 不在本阶段测试的功能

本项目暂不实现和测试机器人充电功能。

原因：

充电功能与当前基础控制器测试逻辑重复度较高，本阶段重点放在机器人控制、工业控制器、Teach Pendant 以及测试设计和自动化测试能力上。

---

## 8. 测试交付物

本项目计划形成以下测试交付物：

- 测试设计文档
- 测试点
